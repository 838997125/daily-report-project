# 示例条目长什么样

这是日报里一条标准条目的写法（非真实数据，仅示意格式）。完整模板见 `skill/templates/daily-report-template.md`。

```markdown
- **事项**：示例项目 —— 修复了什么 / 上线了什么
  - **【问题及影响】**：在什么场景下出现了什么问题，影响哪个环节，不修的风险是什么。
  - **【处理和决策方案】**：最终怎么处理的 + 为什么这样决策；关键技术细节（命令/文件/机制），紧跟一句小白话翻译。
  - **涉及人/部门/系统**：张三 / 运营部 / D3 OMS、钉钉、定时任务。
  - **状态**：已完成 / 进行中 / 阻塞（阻塞要写“需要谁做什么、何时前”）。
  - **📁 项目文档**：
      - 项目设计文档：https://alidocs.dingtalk.com/i/nodes/<设计文档nodeId>
      - 问题与决策档案：https://alidocs.dingtalk.com/i/nodes/<问题档案nodeId>
  - **下一步**：动作 + 负责人 + 时间点。
  - **经验/收获/注意事项**：必填，写给以后避坑。
```

条目排序固定：🔴 阻塞项 > 🟡 进行中 > 🟢 已完成。同一工作主线在一篇日报里只保留一条、融合为最新状态，不开重复条目、不记过程流水账。
